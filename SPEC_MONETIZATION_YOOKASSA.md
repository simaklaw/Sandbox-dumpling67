# SPEC_MONETIZATION_YOOKASSA.md — монетизация через ЮKassa (лицензионные ключи)

## 1. Цель и модель

Продажа «Полного доступа» и контентных наборов **напрямую родителям** через ЮKassa (владелец — самозанятый/НПД). Без RuStore Billing, без рекламных SDK, без рекламы в детском контуре.

**Схема:**
```
Родитель в приложении (раздел «Для родителей», за когнитивным замком)
   → «Купить полный доступ»
   → приложение → НАШ backend: POST /orders
   → backend → ЮKassa: создание платежа (confirmation=redirect)
   → приложение открывает платёжную страницу ЮKassa (Custom Tab/WebView)
   → оплата → ЮKassa → webhook на backend
   → backend помечает заказ оплаченным и выдаёт лицензионный ключ
   → родитель вводит ключ в приложении («Активировать лицензию»)
   → backend возвращает подписанный entitlement → приложение сохраняет в Room
   → игры открываются; дальше интернет не нужен
```

**Железные принципы:**
1. Секреты ЮKassa (`shopId`, `secretKey`, webhook-секрет) **никогда не попадают в Android-приложение и в этот репозиторий** — только в backend (env-переменные).
2. Приложение общается **только с нашим backend**, не с ЮKassa напрямую.
3. Деньги и статус оплаты определяет **только webhook ЮKassa на backend**; клиентский «я оплатил» ничего не значит.
4. Детский контур офлайн и без покупок. Сеть используется только в родительской зоне.
5. Купленное работает офлайн; интернет нужен один раз для активации и периодически для проверки отзыва (возврата).

## 2. Backend (отдельный репозиторий `sandbox-dumpling67-backend`)

Стек: **Python FastAPI** (или Ktor — на выбор владельца; по умолчанию FastAPI) + PostgreSQL/SQLite + Docker.

### 2.1. Конфигурация (только через ENV)
```
YOOKASSA_SHOP_ID=...
YOOKASSA_SECRET_KEY=...
YOOKASSA_WEBHOOK_SECRET=...
SIGNING_PRIVATE_KEY=...        # Ed25519, генерируется владельцем
BACKEND_BASE_URL=https://...
PRODUCTS_JSON=...              # id, цена, название (цены только здесь)
```

### 2.2. Продукты
```json
[
  {"id": "full_access",  "price": 299, "kind": "durable", "title": "Полный доступ"},
  {"id": "winter_pack",  "price": 149, "kind": "durable", "title": "Новогодний набор"},
  {"id": "tip_50",       "price": 50,  "kind": "consumable", "title": "Поддержать 50 ₽"}
]
```

### 2.3. Endpoints

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/v1/products` | Актуальный список продуктов и цен (приложение показывает **эти** цены, никакого хардкода в APK) |
| `POST` | `/api/v1/orders` | Создать заказ → платёж в ЮKassa |
| `GET` | `/api/v1/orders/{orderId}` | Статус заказа + лицензионный ключ, если оплачен |
| `POST` | `/api/v1/yookassa/webhook` | Приём уведомлений ЮKassa |
| `POST` | `/api/v1/licenses/activate` | Активация ключа на устройстве |

**`POST /orders`**
```json
// request
{"product_id": "full_access"}
// response
{
  "order_id": "3f8c…(uuid)",
  "confirmation_url": "https://yookassa.ru/…",
  "amount": {"value": "299.00", "currency": "RUB"},
  "description": "Полный доступ — Детская площадка"
}
```
Внутри: заказ в БД со статусом `pending` + **предсозданный лицензионный ключ** (`status=issued`, ещё не активен) → вызов ЮKassa `POST /payments` с `Idempotence-Key`, `confirmation.type=redirect`, `return_url={BACKEND_BASE_URL}/pay/return?order={order_id}`.

**`GET /orders/{orderId}`**
```json
{"status": "pending|paid|failed", "license_key": "DPLA-XXXX-XXXX-XXXX" /* только если paid */}
```

**`POST /licenses/activate`**
```json
// request
{"license_key": "DPLA-XXXX-XXXX-XXXX", "install_id": "…", "app_version": "…"}
// response (успех)
{"entitlement": "<подписанный токен>", "product_id": "full_access", "activations_left": 2}
// ошибки
{"error": "invalid_key|not_paid|too_many_activations|revoked"}
```

### 2.4. Лицензионный ключ
- Формат: `DPLA-XXXX-XXXX-XXXX`, алфавит без `0/O/1/I/L`, длина 12 символов после префикса.
- В БД хранится **только SHA-256 хеш** ключа; plaintext показывается один раз (страница успеха + раздел «Мои покупки» на сайте, если сделаем).
- Лимит активаций: **3 устройства** на ключ (семейный доступ); `activations` в отдельной таблице по `install_id`.

### 2.5. Webhook ЮKassa (критично)
1. Проверить подпись (`Signature` — HMAC-SHA256 тела с `YOOKASSA_WEBHOOK_SECRET`) и/или сверить `shopId` и сумму платежа с заказом.
2. Идемпотентность по `event_id` (таблица обработанных событий).
3. `payment.succeeded` → заказ `paid` (ключ становится валидным).
4. `payment.canceled` → заказ `failed`.
5. `refund.succeeded` → найти ключ по платежу → `revoked` (приложение отзовёт доступ при следующей проверке).
6. Любая ошибка обработки → лог + ответ 500 (ЮKassa повторит доставку).

### 2.6. Подписанный entitlement
JWT или компактный JSON, подписанный **Ed25519** приватным ключом:
```json
{
  "product_id": "full_access",
  "license_id": "…",
  "issued_at": 1731500000,
  "expires_at": null,
  "v": 1
}
```
Публичный ключ вшивается в приложение — проверка подписи на устройстве, без сети.

### 2.7. Тесты backend
- Проверка подписи webhook (подделка отклоняется).
- Идемпотентность (повторный webhook не выдаёт второй ключ).
- Активация: верный ключ / неверный / не оплачен / превышен лимит / отозван.
- Тестовый режим ЮKassa (test shopId/secret, тестовые карты).

- `app/build.gradle.kts`: зависимости `okhttp` + `kotlinx-serialization` (Retrofit ранее выпилен как неиспользуемый — вернуть в минимальном виде), `BuildConfig` поля: `LICENSE_BACKEND_URL`, `MONETIZATION_ENABLED` (пока `false`, включаем перед запуском).

### 3.2. Новые модули
```
monetization/
  Products.kt                 // модели продуктов
  LicenseApiClient.kt         // HTTP: /products, /orders, /orders/{id}, /activate
  EntitlementVerifier.kt      // проверка подписи токена встроенным публичным ключом
  DirectLicenseGateway.kt     // фасад: продукты, покупка, активация, статус
```
**Правила:** все вызовы только из родительской зоны; таймауты; при ошибке — понятное сообщение, игра никогда не блокируется; никаких секретов и платёжных данных в коде приложения.

### 3.3. Хранение прав (связь с ранее согласованной миграцией)
- Использовать таблицу `entitlements` (Room, версия 6, `MIGRATION_5_6`, `exportSchema=true`) из `SPEC_PHASE1_BILLING.md`.
- После успешной активации: проверить подпись токена → сохранить (`source="direct"`, `kind="durable"`).
- `EntitlementManager.unlockedProducts: StateFlow<Set<String>>` — источник для каталога; работает офлайн из БД.
- При появлении сети (родительская зона) — фоновая проверка отзыва; если ключ отозван → деактивация.
- `resetProgress()` права покупок **не трогает**.

### 3.4. Когнитивный родительский замок (обязателен до покупок)
Заменить двойной тап шестерёнки на когнитивную задачу («нажмите цифру, написанную прописью» / пример со случайными вариантами). Замок охраняет: настройки, магазин, активацию, запись голосов. Тест логики задачи.

### 3.5. Магазин в родительской зоне (`ParentSettingsDialog` или отдельный экран)
1. Список продуктов из `GET /products` (цены — с сервера).
2. «Купить» → `POST /orders` → открыть `confirmation_url` (Custom Tab). Сохранить `pending_order_id`.
3. По возвращении: кнопка «Я оплатил(а) — проверить» → поллинг `GET /orders/{id}`; при `paid` показать ключ и кнопку «Активировать сейчас».
4. Поле «Активировать лицензию» (ввод ключа) — всегда доступно в родительской зоне.
5. Состояния: нет сети («Покупки требуют интернет; купленные игры работают офлайн»), ошибка, ключ неверен.
6. После активации: подтверждение «Полный доступ открыт. Спасибо!»; игры появляются.

### 3.6. Гейтинг каталога (Фаза 2)
