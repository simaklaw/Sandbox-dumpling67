# MONETIZATION_PLAN.md — задание для Claude Code

## 0. Контекст и цель

Приложение «Детская площадка» — офлайн, для детей 2–7 лет, 59 мини-игр. Монетизация — **только через покупки родителями**, не через рекламу ребёнку. Реклама в детском флоу запрещена навсегда. На старте **рекламных SDK нет вообще**.

**Цель MVP:** первые продажи через RuStore за 2 недели, без разрушения офлайн-концепции и без юридического риска.

**Модель:**
- Бесплатно: ~12 спокойных игр (вечный щедрый слой).
- Платно: «Полный доступ» (все игры) + сезонные наборы + опционально «поддержать разработчика».
- Все покупки, цены, магазин — **только в родительской зоне за когнитивным замком**. Ребёнок не видит замков, цен и кнопок покупок.

**Каналы:** `ruStore` (основной, РФ) и `googlePlay` (международный, позже). AdMob в РФ не работает (fill≈0), Play Billing для РФ недоступен — не тратить на них время в MVP.

## 1. Неизменяемые принципы (нарушать нельзя)

1. Детский контур (игры, каталог, главный экран) **не обращается в сеть** и не содержит рекламных/платёжных CTA.
2. Рекламных SDK в v1 **нет**. «Реклама» в будущем = только прямые партнёрские карточки в родительской зоне (без SDK), не раньше отдельного решения владельца.
3. Любой платёжный/рекламный SDK инициализируется **лениво, только при открытой родительской зоне**, не в `Application`/`MainActivity.onCreate`.
4. **Не продавать:** монеты (питают гачу), случайные предметы за деньги, «докупи недостающее к коллекции», временный доступ (72ч и т.п. — контент исчезает у ребёнка = слёзы + эксплойт часов).
5. Цены в UI — **только `formattedPrice` из стора**, никаких хардкодов.
6. Consumable → обязательно `consume`; non-consumable → `acknowledge` + защита от повторной выдачи по `purchaseToken`.
7. Права на покупку — источник истины **стор**, не бэкап. Кэш entitlement нужен только для офлайн-доступа.
8. **Никаких сторонних аналитических SDK.** Конверсия — из консолей сторов + локальные счётчики на устройстве.
9. Схема Room: любые изменения — только через `Migration` + тест; `exportSchema = true` включить сразу (это не меняет схему, а экспортирует её).
10. Каждый пакет — отдельная ветка/PR, зелёный CI, обновление `DEVICE_CHECKLIST.md`. На устройстве агент не проверяет — все device-проверки помечать для владельца.

## 3. ФАЗА 1 — Ядро биллинга (flavors + абстракция + RuStore)

### 1.1. Product flavors (`app/build.gradle.kts`)
- `ruStore` (applicationId суффикс `.rustore` при необходимости) и `googlePlay`.
- `BuildConfig.MONETIZATION_ENABLED` (bool) + `BuildConfig.STORE_KIND`.
- Разрешения: `INTERNET`, `ACCESS_NETWORK_STATE` — **только в манифестах flavor'ов**, не в основном. `AD_ID` не добавлять (для Play kids — вырезать `tools:node="remove"`).
- Зависимости биллинга — по flavor'ам. **Сверить актуальные координаты SDK в документации RuStore** (`rustore.ru/help/developers/monetization`); ожидаемый артефакт `ru.rustore.sdk:billingclient` — подтвердить версию перед подключением.

### 1.2. Абстракция `BillingGateway` (`billing/BillingGateway.kt`)
Единый интерфейс, игры о сторе не знают:
```kotlin
interface BillingGateway {
  val state: StateFlow<BillingState>          // Reactive, не plain-функции
  val products: StateFlow<List<ProductInfo>>  // id, title, formattedPrice
  suspend fun connect()
  suspend fun purchase(activity: Activity, productId: String): PurchaseResult
  suspend fun restore(): List<Entitlement>
  fun disconnect()
}
```
Реализации: `RuStoreBillingGateway` (flavor ruStore), `PlayBillingGateway` (flavor googlePlay, позже), `NoopBillingGateway` (для тестов/отключённой монетизации).

### 1.3. `EntitlementManager` (`billing/EntitlementManager.kt`)
- Room-таблица `entitlements` (productId, purchaseToken, purchaseTime, source, verified). **Версия БД 5→6, Migration + MigrationTest, exportSchema=true.**
- Выдача прав **идемпотентна по purchaseToken** (защита от повторного начисления при каждом коннекте).
- Non-consumable («Полный доступ», наборы) — кэш бессрочный для офлайна; при онлайне сверка со стором, отзыв при refund/revocation.
- `StateFlow<Set<String>> unlockedProducts` — реактивно, игры/каталог читают его.
- **Тесты:** выдача/отзыв/дедупликация/офлайн-кэш/повторный коннект не начисляет дважды.

### 1.4. RuStore-специфика
- Проверка «RuStore установлен»: если нет — в родительской зоне кнопка «Установить RuStore» (deeplink), **не в детском флоу**.
- Graceful: нет сети / нет RuStore / SDK не инициализирован → магазин показывает понятное сообщение, игры работают как обычно.
- Ленивая инициализация: `connect()` вызывается **только при открытии родительского магазина**.

**Acceptance фазы 1:** flavors собираются; `BillingGateway`+`EntitlementManager` с тестами; RuStore-покупка тестового продукта проходит на реальном устройстве (владелец); офлайн-кэш и restore работают; CI зелёный.

## 5. ФАЗА 3 — Продукты и родительский магазин

### 3.1. Продукты (создаёт владелец в консоли RuStore; агент использует константы)
| productId | Тип | Цена-ориентир | Что даёт |
|---|---|---|---|
| `full_access` | non-consumable | 299 ₽ | Все игры + будущие |
| `winter_pack` | non-consumable | 149 ₽ | Новогодний набор (ассеты `ci_winter_*` уже в res) |
| `tip_50` / `tip_150` / `tip_500` | consumable | 50/150/500 ₽ | Поддержка разработчика (значок в credits, без gameplay-перков) |

- Состав `winter_pack` определить по потребителям `ci_winter_*` (скины/сюрпризы/зимний вариант). Разблокировка через entitlement.
- Тип-жар опционален; если делает — consumable + `consume`.

### 3.2. Родительский магазин (`shared/ParentStoreSection.kt` / экран)
- Открывается **только за когнитивным замком** из родительских настроек.
- Карточки продуктов: название, описание, **formattedPrice**, кнопка покупки.
- Кнопка «Восстановить покупки» → `restore()`.
- Состояния реактивно (`StateFlow`): загрузка / доступно / куплено / нет сети / нет RuStore.
- После покупки: явное подтверждение («Полный доступ открыт. Спасибо!»), игры появляются.
- Kill-switch в родительских настройках: «Скрыть магазин» (prefs) + `BuildConfig.MONETIZATION_ENABLED` для поэтапного включения.

**Acceptance фазы 3:** покупка `full_access` открывает все игры; `winter_pack` работает; restore восстанавливает; офлайн-доступ к купленному есть; магазин только за замком; CI зелёный.
